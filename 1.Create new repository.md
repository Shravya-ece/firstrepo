Git Bash Command:

===================

1.gitinit                   ->    To initialize working tree.

2.gitstatus                 ->    To check the staging area status

3.git add                   ->    To add files to the staging area

4.git add .                 ->    To add multiple files to the staging area

5.git commit                ->    Send files from the staging area to local repository

6.git log                   ->    To check the commit history

7.git push                  ->    Send files from local repository to central repository

8.git restore               ->    To restore the staging files to working tree and revert the changes back.

9.git config                ->    To configure username and email id.

10.git clone                ->    To download central repository to local repository

11.git pull                 ->    In order to bring global repository change to local repository.(git pull=git fetch+merge)

12.git fetch                ->    In order to get the changes from central repository to local repository we use git fetch but it cannot merge

&nbsp;                                  from central repository  to working tree                                      

13.git merge <branch-name>  ->   It will merge changes from one branch to another branch and it will preserve commit history.

14.git rebase <branch-name> ->   It will merge changes from one branch to another branch and it will not preserve commit history.

15.git rm                   ->   In order to delete the file from the repository

16.Git clone -b <branch-name><repo-url>->   To clone the repository from the selected branch.

17.git checkout -branch name  ->In order to switch from current branch to another branch.

18.git stash                  ->The changes which are done in the repository and which are not committed can be added to the memory from the

&nbsp;                                 working tree.  

19.git revert <commit-id>      ->The changes which are push to the central repository can be restored to the working tree by using git revert 

&nbsp;                                  command once revert is done then we must push

Git Branches:

=================

=>Multiple teams will be working  on the project parallelly like below:

&nbsp;->On going development

&nbsp;->Bug fixing

&nbsp;->POC/RED (proof of concept)

&nbsp;->Production support

=>When all these team members merging their code changed then it is very difficult to differentiate which code changes are done by which team in repository.

=>To overcome these problems, we will get branches .

=>Git branches are used to maintain separate code bases for the multiple teams working in the same project.



**used to transfer the changes from one branch to another branch.**

2.git merge <branchname>  ->Maintains the commit history.

3.git rebase  <branchname>  ->Not maintains the commit history
